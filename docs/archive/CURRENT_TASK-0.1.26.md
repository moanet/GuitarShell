## 1. 目标

- 记录页首屏以「看记录」为主，不再让常驻录入表单占掉近三分之一屏高。
- 录入表单默认折叠为一行摘要；点按摘要行展开，填写后保存，保存成功自动收起。
- 折叠状态只保留摘要行，趋势区与记录列表整体上移约 150px。
- 360×800、表单与趋势均收起、有 6 条记录时，首屏至少完整显示 4 条记录。
- 趋势图、TOP5、累计统计、分享卡、记录列表与删除逻辑都不改。

## 2. 非目标

- 不改页面区块顺序：仍是「表单摘要 → 练习趋势 → 记录列表标题 → 记录列表」；不把趋势搬到表单上方。
- 不改趋势的默认收起状态、近 7 天 / 近 12 月切换、`gs_trend_range` 记忆、分享卡入口与内容。
- 不改记录卡片的字段、顺序、删除确认与数据库结构。
- 不新增快速打卡模板、常用曲目、最近曲目、时长步进器、自动计时或表单分步。
- 不改顶部 App 标题栏、四 Tab、全局设置抽屉。
- 不为此版引入动画库；折叠 / 展开用即时显隐，不做高度动画。
- 不做练习记录编辑、筛选、日历热力图；这些仍在 backlog。

## 3. 交互与实现

### 3.1 默认折叠与摘要行

- 组件首次挂载默认折叠，不记忆上次展开状态；切换 Tab 再回来保持当前状态。
- 摘要行为整行可点击按钮，最小高度 `48px`，左侧铅笔图标 + 「记录本次练习」，中间摘要，右侧 `▸ / ▾`。
- `aria-expanded` 与 `aria-controls="formBody"` 同步；键盘 Enter / Space 可展开 / 收起。
- 摘要文案由 `getTodayPracticeSummary(currentLogs)` 生成：
  - 今天没有记录：`今天还未打卡`，用 `var(--muted)`；
  - 今天有记录：`今天 N 次 · M 分钟`，次数与分钟用 `var(--accent-text)` 强调。
- 摘要行在 320 宽仍单行；标题不换行，摘要 `max-width` 受限并省略，箭头始终可见。
- 摘要行沿用现有 `surface-deep` 背景与底部细线，不新增大卡片或阴影。

### 3.2 展开表单

- 展开后显示原有三件套：练习内容、练习时长、最高 BPM、保存按钮；字段顺序、校验、placeholder、`maxlength` / `min` / `max` 不变。
- 展开时在字段上方保留一行 `form-hint`「填写后点保存」；折叠时该行隐藏。
- 展开不自动聚焦、不自动弹软键盘；用户点输入框再输入。
- 收起时若焦点在任一输入框，先 blur 再隐藏，确保 Android 软键盘收起。
- 收起不清空已输入内容；再次展开，未保存的曲目 / 时长 / BPM 仍在。
- 摘要行本身只负责展开 / 收起，不触发表单提交。

### 3.3 保存与列表联动

- 校验失败保持展开，toast 与现有文案不变，输入内容不丢。
- 保存成功：清空三个输入框、toast「打卡成功！」、刷新列表与趋势、更新今日摘要，然后自动折叠。
- 自动折叠后列表立即上移；不强制滚动到顶部，不改变用户当前列表滚动位置以外的状态。
- 看谱器广播 `log-updated` 时仍只刷新数据，不主动改变表单展开状态。
- 今日摘要只在 `loadLogs` 后重算；删除记录后同步更新。

### 3.4 趋势与列表

- 趋势区默认仍收起；展开 / 收起、图表、TOP5、累计统计、分享按钮都复用现有实现。
- 表单展开 / 收起不联动趋势，不自动展开或收起趋势。
- 「练习记录列表」标题与 `listCount` 不动；列表继续占满剩余高度并独立滚动。
- 页面本身仍不产生第二层整页滚动；表单展开后列表变短属预期。

### 3.5 布局与主题

- 折叠态 `form-box` 高度约 `48–50px`，只保留摘要行；展开态高度约 `214px`，不超过 `220px`。
- 360 / 320 均无横向溢出；浅色 / 深夜两套主题只使用现有 CSS 变量，不新增硬编码颜色。
- 记录卡片保持现有 360 布局；320 下 `.log-detail` 的既有收缩规则不变。

## 6. 风险

- **摘要行可点击性不足**：只有文字和箭头时容易被当成静态标题；整行必须是按钮，箭头方向明确，点按区域覆盖全宽。
- **折叠后不知道今天练了多少**：摘要必须承担今日状态，否则折叠会让信息更少。
- **软键盘残留**：仅 `display:none` 不一定立刻收键盘；收起前主动 blur。
- **保存后页面跳动**：自动折叠与列表刷新同时发生，需先清空再折叠，避免用户看到旧内容一闪。
- **趋势与表单状态耦合**：两个折叠区必须独立，互不自动开关。
- **320 摘要挤压**：标题、摘要、箭头三者竞争宽度；摘要必须可省略，不能把箭头挤出屏。
- **列表滚动位置**：保存后新增记录在顶部，若用户原本在列表中部，不应强行拉回顶部；只在自然刷新后保持可用。
