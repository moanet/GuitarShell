## 1. 目标

按 `v1.1` 逐页推广计划，先把**调音器主页面**收口到规范：统一页面边距、字号层级、按钮/状态语法、触控热区和双主题，不改调音业务。

调音设置外壳已在 P9 完成，不在本轮重复；乐谱、记录、阅读器在后续各自任务书中推广，不把样板值机械复制到本页。

## 2. 非目标

- 不改全局头部、Tab、版本胶囊、全局设置抽屉。
- 不改调音器设置外壳（固定头部 / 滚动内容 / 底部完成已在 P9 完成）。
- 不改 YIN 检测、麦克风权限、六弦识别、A4 步进、标准音试听、音分曲线、离页关麦等业务逻辑。
- 不改调音器指针新 token / 去光晕、主仪表造型；D3/D6 实验项仍留 v1.2。
- 不改自定义调弦编辑和音高选择器的交互，只检查它们与主页面外壳的一致性。
- 不做全应用 UI 大扫除，不重排信息架构。

## 3. 范围与涉及文件

| 文件 | 用途 |
|---|---|
| `js/components/tuner.js` | 调音器主页面样式、状态和布局；只改视觉层，不动检测逻辑 |

| `tests/browser/gs_026.py` | 调音器主界面、设置、自定义、选择器回归；按本轮改动补断言 |
| `tests/browser/README.md` | 只同步调音器新增断言与截图说明 |

截图、临时 APK、测试产物不入库。

## 4. 已锁定交互

- 调音器仍以仪表为主，不改成卡片列表；主读数、Hz、频差条、弦位行的层级保持现有产品语义。
- 底部“设置”仍是文字动作按钮；设置弹层仍按 P9 外壳打开和关闭。
- 弦位行、开始/停止、标准音、提示音、震动、A4 的行为不变。
- 双主题、320/360 边界继续作为验收面；320 不作为真实窄屏专项，但不得横向溢出。
- 只对触达的控件补 44 热区、焦点环；不顺手改无关控制。

## 5. 实施顺序

1. **P1 基线审计（只读）**：在 360/320、深夜/暖纸下截主界面，记录计算样式与规范差异，列成表；不改代码。
2. **P2 视觉收口**：按审计表处理页面边距、字号层级、按钮/状态、触控热区；优先改长句和关键状态，不新增中间字号。
3. **P3 自动化**：跑 `gs_026.py`（360 深/浅、320 浅）与 `npm run check`；按实际改动补断言和 README。
4. **P4 真机抽验**：需要时构建 dev APK，在 `ca14b16` 抽看浅/深主界面、设置打开/关闭、A4、弦位行和标准音；结束时恢复设备并明确交还。

## 6. 验收标准

- 调音器主页面在 360/320、深/浅下无横向溢出，关键文字可读，触控热区不小于 44。
- 主界面与 P9 设置外壳的标题、边距、按钮和关闭路径一致；不出现重复 X。
- `gs_026.py` 通过，`npm run check` 通过；新增断言与 README 同步。
- 真机抽验通过后，设备恢复浅色书架并交还；不 bump 版本、不发 Release。
- 审计表和实际改动一致；未完成的 D3/D6 实验项继续留在 v1.2，不混入本轮。
