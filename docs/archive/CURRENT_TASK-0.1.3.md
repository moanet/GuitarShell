## 1. 目标

0.1.3 不加新的大功能，先把“数据不重复、同步状态看得见”这两件事做扎实：

1. 乐谱导入按**内容哈希**去重，改名后的同一份文件不再重复入库。
2. 旧库中没有哈希的乐谱，在再次导入同尺寸文件时惰性回填哈希，并参与判重。
3. 云同步面板显示“上次同步时间 / 本机是否有未同步改动”，上传或下载成功后立即刷新。
4. 为备份恢复补上 `updatedAt`，让标签、进度等改动能被同步状态识别。

## 2. 范围

### 做

- 新增 `js/services/file-hash.js`：优先 SHA-256，浏览器不支持时回退 FNV-1a 64。
- 导入时计算文件哈希；哈希相同即判定重复，名称 + 大小只作为旧记录的兼容回退。
- 旧记录没有 `fileHash` 且尺寸相同时，按需计算并写回，不一次性扫描全库。
- 云同步状态抽到 `js/services/sync-state.js`，读谱页弹窗与全局设置共用。
- `dbService.updateScore()` 写入 `updatedAt`；本机改动时间戳纳入 `updatedAt`。
- 本地备份、云备份、恢复流程都保留 `fileHash` 与 `updatedAt`。

### 不做

- 不做自动定时云同步；仍是手动上传 / 下载。
- 不做云端双向合并或自动冲突解决。
- 不做全拼 / 模糊搜索；本轮只保留现有首字母搜索，下一版再评估。
- 不改 IndexedDB `DB_VERSION`；新增字段按缺省值兼容。
- 不改变现有导入格式、大小限制和书架布局。

## 3. 已拍板决策

### 3.1 哈希去重

- 哈希格式带算法前缀：`sha256:<hex>` / `fnv1a64:<hex>`，避免不同算法结果误判相等。
- 同一内容、不同文件名：跳过，提示“跳过重复”。
- 同名同大小但内容不同：不判重，正常导入；有哈希时以哈希为准。
- 旧记录只对“同尺寸候选”做惰性哈希，不扫描全部乐谱 Blob。
- 哈希失败不阻断导入：退回名称 + 大小判重，并在控制台记录失败原因。

### 3.2 同步状态

- “上次同步”以当前云端路径的 `gs_cloud_sync:<path>` 为准；换路径不误用旧记录。
- 本机改动时间取 `createdAt / updatedAt / lastReadAt` 的最大值。
- 从未同步且本机有数据：显示“尚未同步 · 本机有 N 份乐谱 / M 条记录”。
- 上次同步后本机有改动：显示“上次同步 … · 本机有未同步改动”。
- 本机没有新改动：显示“上次同步 … · 本机已是最新”。
- 上传 / 下载成功后立即刷新状态；不上传、不下载时只展示，不自动弹窗。

## 5. 风险与边界

- SHA-256 在非安全上下文可能不可用；FNV-1a 只用于本机判重，不作为安全校验。
- 大 PDF 计算哈希会增加导入等待；界面显示“正在校验文件”，不冻结书架。
- 旧记录惰性回填只在同尺寸候选上发生，首次可能稍慢，但不会全库扫描。
- 同步状态只代表本机记录，不代表云端真实内容；云端是否变化仍以 WebDAV `stat` 为准。
- `updatedAt` 是新增字段，不升 `DB_VERSION`；旧记录缺省为 0，不影响读取。
