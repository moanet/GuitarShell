## 1. 目标

0.1.6 只做“乐谱拆分建卡”，补读谱器最后一个硬缺口：

- 用户在一份多曲 PDF 里读到某首曲子时，可以选中页段，生成一张独立乐谱卡。
- 原谱保持不变；新卡与页段是独立 PDF，不依赖原文件。
- 拆分后的卡片可以正常阅读、存进度、加书签、备份与云同步。

## 2. 方案

### 2.1 存储方式

采用“独立 PDF”：

- 用 `pdf-lib` 读取原 PDF，按页段复制页面，生成新的 PDF Blob。
- 新卡写入 IndexedDB 的新记录，拥有自己的 `fileBlob`。
- 不新增数据库版本，不保存“虚拟页段引用”，不依赖原谱 id。
- 删除原谱不会影响新卡；删除新卡也不会影响原谱。

### 2.2 入口与交互

入口放在阅读页工具栏，只在 PDF 阅读时显示：

- 按钮文案：`✂ 拆分`。
- 默认起始页为当前阅读页，结束页同起始页。
- 弹窗显示原谱总页数，并实时提示“将抽取第 a–b 页，共 N 页”。
- 新卡名称默认 `${原谱名} · P${start}` 或 `${原谱名} · P${start}-${end}`，可手动修改。
- 新卡沿用原谱标签；标签可在建卡后再编辑。
- 建卡成功后刷新书架并提示，不自动跳转，避免打断当前阅读。

### 2.3 页段校验

- 起始页、结束页必须是整数。
- 范围必须落在 `1..总页数`。
- 起始页不得大于结束页。
- 非法范围时禁用“建卡”，并显示具体错误。
- 加密或损坏 PDF 读取失败时提示“无法拆分”，不写入任何记录。

### 2.4 依赖

- 引入 `pdf-lib 1.17.1` 浏览器 ESM 包，放在 `js/lib/pdf-lib.esm.min.js`。
- 只有用户点击“拆分”后才动态加载，不进入首屏执行路径。
- 许可证放在 `js/lib/pdf-lib.LICENSE.md`。
- 新文件加入 `sw.js` 缓存清单，保证离线可用。

## 5. 风险与边界

- 独立 PDF 会额外占用页段体积；原谱越大、拆得越多，占用越高。
- `pdf-lib` 约 523 KB，APK 体积会增加；只在拆分时加载，不影响普通阅读。
- 大 PDF 复制页面可能短时占用较多内存；失败时不写入记录。
- 拆分只复制页面内容，不保证保留原 PDF 的书签、表单、附件等文档级结构。
- 不提供页预览缩略图；首版用页码输入，后续可补预览与“读到结束页自动填入”。
- 不做批量拆分、不做按目录自动识别曲目、不删除原谱。
- 新卡是普通乐谱记录，不保存“拆分自哪本谱”的来源关系；后续需要溯源时再加字段。
- 云同步与备份会把原谱和新卡各自打包；空间成本由用户可见的数据量承担。
