# CURRENT_TASK — 0.1.14b 自定义背景

> 版本：`0.1.14b` / `versionCode 119`
> 上一版：`0.1.14a`（提交 `58a0974`，已真机验收并推送 `main`；tag 与 Release 继续压后）
> 本阶段：分享卡片第 7 套背景——从系统相册选图、轻量裁切、压缩、压暗蒙版、资产统计与清理联动
> 原则：只做本机内容，不上传、不请求远程模板；六套预设背景保持不变

## 1. 目标与边界

### 1.1 要达成的结果

- 预览页背景色板末尾增加第 7 个「自定义」入口，可相册选图并立即预览。
- 图片经轻量裁切页定为 3:4、压缩为 1080×1440 JPEG，存入 IndexedDB。
- 自定义背景上叠加可调「压暗蒙版」，保证文字对比度；选择持久化。
- 自定义背景计入存储统计；清理未引用缓存时只删除失效副本，绝不删除当前使用中的背景。
- 六套预设背景、现有保存/分享链路、卡片版式全部不回退。

### 1.2 本阶段不做

- 不做自由裁切编辑器：只做 3:4 取景框内的拖动与 1×–3× 缩放，不做旋转、网格微调、比例切换。
- 不做滤镜、模糊、亮度/对比度调色、多张自定义背景槽位。
- 不把自定义背景写入本地备份或云同步；恢复后若指针失效，回退 `walnut`。这是本阶段默认决策。
- 不发布 tag / GitHub Release，等 `0.1.14c` 验收后统一处理。
- 不改六套预设参数与卡片坐标。

## 2. 交互规格

### 2.1 背景色板

现有 6 个 28px 色板后追加第 7 个「自定义」：

- 无自定义图：虚线圆角方块，中间 `＋`，`aria-label="添加自定义背景"`。
- 已有自定义图：28px 缩略图（`object-fit: cover`），选中时与预设相同的暖色描边。
- 点击行为：
  - 没有图 → 打开系统相册选 1 张，进入裁切页。
  - 已有图但当前未选中 → 选中自定义并立即重绘。
  - 已有图且已选中 → 无动作（更换走下方操作行）。
- 选中自定义时，色板下方出现工具行：
  - `压暗 60%` + 滑块（60–90，步进 2）。
  - `更换图片`。
  - `移除`。
- 未选中自定义时工具行隐藏；已存的自定义图和指针保留，切回预设不会删除。
- 窄屏 320px：色板允许横向滚动，不换行、不压缩预设色板尺寸。

### 2.2 选图

- 原生壳：复用 `GalleryPicker.pickImages`，`limit: 1`；返回缓存文件经 `convertFileSrc` + `fetch` 转 `File`。
- 小米兼容：部分 MIUI 设备上系统 `ACTION_PICK_IMAGES` 的 `PhotoPickerActivity` 会创建后立即 `finish`。`GalleryPickerPlugin` 在 Xiaomi 且 `com.miui.gallery/.picker.PickGalleryActivity` 可解析时优先走 MIUI 相簿（`ACTION_GET_CONTENT` + `CATEGORY_OPENABLE` + `image/*`），否则 Android 13+ Photo Picker，再退 `OPEN_DOCUMENT`、`GET_CONTENT`。
- 网页：隐藏 `<input type="file" accept="image/*">`，只能选 1 张。
- 取消选择：静默恢复，不弹错误 toast。
- 选图/处理期间：保存、分享、曲名开关、所有色板、工具行互斥禁用；状态文案「正在处理背景…」。
- 处理失败：toast 明确原因（格式不支持 / 图片过大 / 读取失败 / 压缩失败），保留原背景与旧图。

### 2.3 裁切页

选图后先进入轻量裁切页，再压缩入预览：

- 3:4 取景框，初始 `cover` 铺满并居中，缩放 1.0×。
- 单指/鼠标拖动调整位置；双指捏合 1×–3×；双击或「恢复居中」回到初始位置。
- 触屏 WebView 不保证派发 `dblclick`，实现同时对 `pointerup` 做手动双击判定：单指、非 mouse、位移 ≤8px、按下时长 <320ms，且距上次 tap <36px / <340ms。
- 边界约束：任何时候图片都铺满取景框，不露黑边。
- 底部「取消 / 使用这张」；取消回到原背景，不改任何资产。
- 关闭按钮、点遮罩、返回键都等同取消；裁切页是预览之上的独立返回层。
- 确认时按同一取景结果导出 1080×1440，不把屏幕坐标或缩放比写进资产。
- 320px 宽、短屏（≤640px 高）取景框自动缩小，按钮不溢出。

### 2.4 压缩

- 解码优先 `createImageBitmap(file)`，不可用时回退 `Image` + object URL。
- 裁切页确认后按 3:4 输出 1080×1440。
- 输出 `image/jpeg`：
  - 首选质量 `0.82`；若结果 > 900 KB，依次降为 `0.72`、`0.62`。
  - 仍 > 900 KB 则拒绝，提示「图片压缩后仍超过 900 KB，请换一张」。
  - 源文件 > 20 MB 直接拒绝。
- 输出尺寸必须严格 `1080×1440`，元数据 `width=1080`、`height=1440`、`mime='image/jpeg'`。
- 没有裁切页时的 `processCustomBackground(file)` 仍保留自动中心裁切，作为回退与数据层测试入口。

## 3. 压暗蒙版与卡片渲染

### 3.1 蒙版

- 自定义背景固定使用深色文字方案，不再按图片明暗切浅色文字。
- 在图片上叠加两层：
  1. 全局黑色蒙版，透明度 = 用户「压暗」值（0.60–0.90，默认 0.60）。
  2. 轻径向暗角，中心透明、边缘 `rgba(0,0,0,0.38)`，保持与预设一致的收边。
- 工具行文案显示整数百分比；拖动时实时重绘，松手后写 `localStorage`。
- 默认 `60%`；最低 `60%`。验收需覆盖纯白图片 + `60%` 时的对比度：主文字 ≥ 5:1、弱化文字 ≥ 4.5:1、强调色 ≥ 3:1。
- 自定义背景的强调色与文字：
  - strong `#FBF4E9`
  - muted `#F1E9DE`
  - accent `#F0B67A`
  - 题记使用 strong 55% 透明度；页脚线、分隔线沿用 accent 低透明。

### 3.2 绘制

- `drawShareCard()` 新增 `background: 'custom'`、`customImage`、`customDim` 参数。
- 自定义图按 1080×1440 直接绘制，再叠蒙版与暗角；不重复裁切。
- 没有 `customImage` 或资产读取失败时，本次渲染回退 `walnut`，并清除失效指针。
- `SHARE_BACKGROUNDS` 仍只保留六套；新增独立 `CUSTOM_SHARE_BG` 配置，避免预设数量断言变化。
- `canvas.dataset.background` 自定义时为 `custom`；`dataset.customDim` 记录实际值，供回归读取。

## 4. 数据与存储

### 4.1 IndexedDB

复用现有 `assets` store，不升 `DB_VERSION`。新增资产：

```js
{
  kind: 'share-bg',
  blob: Blob,            // image/jpeg
  mime: 'image/jpeg',
  width: 1080,
  height: 1440,
  bytes: blob.size,
  sourceName: string,    // 仅记录原文件名，可为空
  createdAt: number
}
```

- 不写 `scoreId`。
- 替换时先新增资产并写指针，成功后再删除旧资产；删除旧资产失败不阻断新图使用，残留交给孤儿清理。
- 移除时先清指针，再删除资产；删除失败也回退 `walnut`，残留下次清理。
- 旧指针指向不存在/类型不符/无 blob 的资产：按失效处理，清指针并回退。

### 4.2 localStorage

- `gs_share_bg`：六套 id 或 `custom`；非法值回退 `walnut`。
- `gs_share_bg_asset`：当前自定义资产 id（字符串）。
- `gs_share_bg_dim`：压暗百分比整数字符串（60–90），默认 `60`。
- 切换预设只改 `gs_share_bg`，不删资产、不清 `gs_share_bg_asset`。
- 移除自定义时清 `gs_share_bg_asset`，`gs_share_bg` 置 `walnut`。

### 4.3 统计

`collectStorageStats()` 增加：

- `backgroundCount`：`kind === 'share-bg'` 数量。
- `backgroundBytes`：这些资产的 `bytes` 合计。
- `imageCount = coverCount + backgroundCount`
- `imageBytes = coverBytes + backgroundBytes`
- `usage` 估算回退改为 `scoreBytes + imageBytes`。

设置页存储卡：

- 第三格标题由「封面缓存」改为「图片缓存」，数值显示 `imageBytes`。
- 保留元素 id `coverUsage`，减少回归改动；测试同步改为断言图片缓存合计。
- 配额提示前补「封面 X 张 · 自定义背景 Y 张」。
- `清理封面缓存` 仍然只删 `kind === 'cover'`，不得碰自定义背景。

### 4.4 孤儿清理

- `findOrphanAssets()` 规则改为：
  - `cover`：沿用“无乐谱持有或指针不匹配”判孤儿。
  - `share-bg`：仅当 id 等于 `gs_share_bg_asset` 时保留；其余全部判孤儿。
  - 其他未知 kind：判孤儿。
- 当前使用中的自定义背景即使 `gs_share_bg` 是预设，也必须保留（用户可能切回）。
- `clearOrphanAssets()` 删除范围随之扩大；确认弹窗文案改为“只删除失去引用的封面和自定义背景缓存；当前背景、乐谱与练习记录不受影响”。
- 清完缓存后设置页数字刷新；若当前自定义被手动移除，立即回退并重绘。
